# 📦 Storage & Models

How files and AI models are stored, accessed, and synchronized.

---

## Storage Overview

There are **two storage systems**:

| Storage | Location | Purpose | Speed |
|---------|----------|---------|-------|
| **Local NVMe** | `/vol/service/cw/storage-models/models/` | AI models | ⚡ Very fast |
| **NAS (SMB)** | `/mnt/nas/storage-user/` | User files (images, datasets) | 🐢 Slower (network) |

**Why two?** AI models are huge (2–20 GB each) and need to load fast. The local NVMe drive provides instant access. User files (generated images, training data) are stored on the NAS so everyone in the office can access them.

## Model Storage

### Where Models Live

All AI models are stored on the server's local drive at:
```
/vol/service/cw/storage-models/models/
├── checkpoints/      ← Full AI models (SD 1.5, SDXL, FLUX, etc.)
├── loras/            ← LoRA fine-tuning models
├── vae/              ← VAE models (image decoder/encoder)
├── controlnet/       ← ControlNet models (pose, depth, etc.)
├── embeddings/       ← Textual inversion embeddings
├── clip/             ← CLIP text encoder models
├── clip_vision/      ← CLIP vision models
├── diffusion_models/ ← Diffusion model files
├── upscale_models/   ← Upscaling models (ESRGAN, etc.)
├── text_encoders/    ← Text encoder models
├── hypernetworks/    ← Hypernetwork models
├── vae_approx/       ← VAE approximation models
└── configs/          ← Model configuration files
```

### Adding New Models

**Option 1 — Download directly on the server:**
```bash
# SSH into the server
ssh user@192.168.0.10

# Download a model (example: a checkpoint from CivitAI or HuggingFace)
cd /vol/service/cw/storage-models/models/checkpoints/
wget https://example.com/model.safetensors

# Or for LoRAs:
cd /vol/service/cw/storage-models/models/loras/
wget https://example.com/lora.safetensors
```

**Option 2 — Copy via SCP from your computer:**
```bash
scp my-model.safetensors user@192.168.0.10:/vol/service/cw/storage-models/models/checkpoints/
```

After adding models, they're immediately available in all services — no restart needed (though you may need to click "Refresh" in the service's model list).

### Model Sync to NAS

To back up models from the local drive to the NAS:
```bash
# Run on the AI server
rsync -av /vol/service/cw/storage-models/models/ /mnt/nas/storage-user/models/
```

To restore models from the NAS to a fresh server:
```bash
rsync -av /mnt/nas/storage-user/models/ /vol/service/cw/storage-models/models/
```

## User File Storage (NAS)

### Folder Structure on the NAS

Access via Windows: `\\192.168.0.6\ki_Daten\storage-user\`
Access via macOS: `smb://192.168.0.6/ki_Daten/storage-user/`

```
storage-user/
├── input/                ← Upload images here for img2img, inpainting, etc.
├── output/
│   ├── ComfyUI/          ← Images generated by ComfyUI
│   ├── Fooocus/          ← Images generated by Fooocus
│   ├── Forge/            ← Images generated by Forge
│   ├── InvokeAI/         ← Images generated by InvokeAI
│   └── AIToolkit/        ← Training outputs from AI Toolkit
├── workflows/            ← Saved workflows (ComfyUI, etc.)
└── datasets/             ← Training image sets for AI Toolkit
```

### How to Use Input Images

1. Copy your images to `\\192.168.0.6\ki_Daten\storage-user\input\`
2. In the AI service, browse to the input folder
3. Services mount this folder read-only to prevent accidental deletion

### Where Generated Images Go

Each service automatically saves generated images to its own folder on the NAS. You can browse them from any computer on the network.

### Training with AI Toolkit

1. Create a folder for your training images in `\\192.168.0.6\ki_Daten\storage-user\datasets\`
2. Copy 10–50 training images into that folder
3. In AI Toolkit, set **Dataset Folder Path** to `datasets`
4. Set **Training Folder Path** to `outputs`
5. Start training — results will appear on the NAS

## SMB Mount Configuration

The NAS is mounted on the server via CIFS/SMB. If the mount stops working:

```bash
# Check if NAS is mounted
mount | grep nas

# Re-mount
sudo mount -a

# Test connection to NAS
ping 192.168.0.6

# Test SMB access
smbclient -m SMB3 //192.168.0.6/ki_Daten -U d3kiserver
```

The mount is configured in `/etc/fstab` — see [04 — Getting Started](04-getting-started.md) for details.
